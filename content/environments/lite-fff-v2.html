FFFLite V2¶

Scope¶

lite/fff-v2 is a fast 2D kinematic source-motion and deposition/fill surrogate. It rasterizes a source footprint and accumulates deposited occupancy. It does not model heat transfer, extrusion rheology, bonding, stress, displacement, layers, material conservation, or quantitative DAWN FFF physics.

Use V2 for inexpensive control studies where the relevant semantics are source motion, source activity, target coverage, and spill outside a target. Do not describe its deposited-occupancy channel as a thermodynamic phase or claim that a Lite outcome is physically or numerically equivalent to DAWN.

Version and replay boundary¶

Surface

Contract

lite/fff, ctrlp/lite-fff-v0

frozen exact-replay surface for existing controls, snapshots, checkpoints, VecNormalize state, traces, and results

lite/fff-v2, ctrlp/lite-fff-v2

independent source and artifact tree for new kinematic studies

V0 versus V2 trained from scratch with paper1 controls

study-level comparable

V0 checkpoint loaded as V2

unsupported; no redirect, copy, or automatic migration

V2 versus DAWN FFF

semantic/kinematic alignment only

Existing V0 controls keep resolving to V0. New work must select lite/fff-v2 explicitly. V2 outputs belong below experiments/lite/fff-v2/runs/; never copy V0 snapshots, checkpoints, normalization state, evaluations, or results into that tree.

Coordinates and update order¶

  • Config vectors are [x, y].

  • Arrays are (row=y, column=x).

  • Arrays keep the Paper 1 image convention: row indices increase downward.

  • The default/demo action profile follows DAWN FFF world controls: U=[0,1], D=[0,-1].

  • grid.cells is [nx, ny] for the unpadded interior.

  • grid.length_m is the unpadded interior size.

  • padding_cells: 1 produces (ny + 2, nx + 2) arrays.

  • Paper 1 cell_relative positions select over the complete padded policy grid.

Movement is direction * speed_m_per_s * step_duration_s. Each step applies the action first and then deposits at the realized position when the source is active. Toggle-on therefore deposits immediately; toggle-off does not. An out-of-bounds move leaves the source in place, reports invalid_action, and still deposits there when active. Reset never deposits merely because ProcGen starts the source active.

Observation and action contract¶

The default observation is a float32 Box(0, 1) with channels:

Channel

Meaning

mask.processed

cumulative binary deposited occupancy, not thermodynamic phase

source.0.field

current footprint: 1.0 active, 0.5 inactive, 0.0 elsewhere

mask.target

binary target occupancy

These are the current physical-state-v1 observation selectors. Historical short names require an explicit contract conversion; they are not aliases in new V2 controls. See the shared physical-state contract.

The default actions are L, R, U, D, and TOGGLE, with the same vectors and arrow-key bindings as maintained DAWN FFF fill controls. The versioned Paper 1 controls explicitly preserve the historical image-frame convention U=[0,-1], D=[0,1] and A/D/W/S/SPACE bindings.

The default source moves exactly one grid cell per action at both shipped resolutions and uses a one-cell footprint, matching DAWN FFF xy_step_cells: 1 and load.sigma: 0. Toggle and action-then-deposit ordering also match. This is semantic alignment only, not physical equivalence.

Visualization¶

V2 uses the same schema-driven PhysicalSceneBuilder, RenderScene, and FieldViewer pipeline as Dawn FFF, Lite PBF V2 and the Dawn PBF adapter. Its composite panel displays cumulative deposited occupancy with target and source overlays. No nominal or display-only temperature is created. Geometry remains in the same physical units as the canonical state, while camera and cell-height adjustments remain presentation-only.

Step info includes score, procgen, is_success, task_complete, termination_reason, invalid_action, reward_terms, and kinematics. is_success is true only on objective completion. A vector time limit is a truncation, not success. Objective termination includes terminal_observation.

Determinism and vectorization¶

reset(seed=s) reseeds Gymnasium and ProcGen. Repeating the same seed repeats the sampled parameters, mask, source state, initial observation, and action trace. reset(seed=None) continues the ProcGen sequence. Vector workers use base_seed + rank, and the model has no global random generator or wall-clock state. The generic dummy and subprocess vector wrappers are sufficient.

Paper 1 profile¶

Four source-owned controls reconstruct the historical actions, three channel meanings, ProcGen splits, reward terms, algorithms, budgets, and evaluation protocol:

  • depo_small/ppo/paper1

  • depo_small/dqn/paper1

  • depo_medium/ppo/paper1

  • depo_medium/dqn/paper1

The small and medium observation shapes are 3 x 12 x 12 and 3 x 22 x 22. These controls support a from-scratch, study-level comparison. They do not promise checkpoint compatibility, identical rewards, identical traces, or numerical equality with V0.

Canonical evaluation uses procgen-v1/lite-fff-v2/depo-small and procgen-v1/lite-fff-v2/depo-medium. Their geometric scenario CSV payloads match V0 byte-for-byte, while their benchmark IDs, environment IDs, manifests, and fingerprints remain V2-specific.

Commands¶

ctrlp experiments/lite/fff-v2/runs/depo_small/ppo/smoke/run.yml --mode resolve
ctrlp experiments/lite/fff-v2/runs/depo_small/ppo/smoke/run.yml --mode check
ctrlp experiments/lite/fff-v2/runs/depo_medium/ppo/smoke/run.yml --mode check
ctrlp experiments/lite/fff-v2/runs/depo_small/ppo/smoke/run.yml --mode train --envs 1

For controller-independent manual and path demonstrations, use:

python -m ctrlp.environments.lite.demo --env fff-v2 --controller keyboard
python -m ctrlp.environments.lite.demo --env fff-v2 --controller gcode \
  --path examples/lite/fff-zigzag.gcode

Keyboard, G-code, and direct callers share the SI-valued ProcessCommand boundary below Gymnasium. G-code movement is interpolated rather than teleported, so an active FFF source deposits along the full realized segment.

Generalization profile (opt-in)¶

The default and Paper 1 profiles remain unchanged. A new observation profile may set env.obs.grid: [x, y]; the native (y, x) fields are conservatively projected onto that fixed physical policy grid. Optional context planes may be listed in env.obs.context: valid, normalized x/y, and domain_x/domain_y. Domain planes require env.obs.context_reference_m: [x_m, y_m] and are metadata, not hidden simulator state. The resolved representation is recorded as fixed-policy-grid-v1.

Before loading a checkpoint, compare build_policy_transfer_contract results. Exact tensor shape only permits a load when channel meanings, action semantics, normalization, process type, and configuration provenance also match. Use resolve_paired_benchmark to verify that Lite V2 and DAWN consume one immutable scenario bank; this is an evaluation-provenance check, not evidence of task-performance transfer.

The policy-transfer preflight is maintained in private research tooling; students should use check on the source and target controls before running a short held-out rollout.

Versioned ProcGen difficulty¶

New cross-environment baseline studies should use the shared Lite V2 ProcGen difficulty presets. They add explicit easy-to-hard levels with letters for training, symbols for validation, geometric shapes for testing, and native boundary-safe shape-fit-v1 sizes. The historical default and Paper 1 profiles remain unchanged.
