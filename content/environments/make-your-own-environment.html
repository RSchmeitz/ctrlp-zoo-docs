Make Your Own Environment¶

Use this guide to choose the Gymnasium adapter or add a built-in environment.

Choose The Right Path¶

Goal

Recommended path

run a standard benchmark such as CartPole-v1

use the generic Gym bootstrap

add a real CTRL-P environment with package defaults

create a new package under src/ctrlp/environments/

add custom reward/model/state logic

create a real built-in environment package

use ProcGen scenarios

create a real built-in environment package

Option 1: Use a Standard Gymnasium Environment¶

For a standard Gymnasium environment, create a run config such as experiments/cartpole-v1/runs/default/ppo/default/run.yml:

select:
  env: cartpole-v1
  task: default
  algo: ppo
  run: default
presets:
  procgen: default
  reward: default
  vec: default

On the first executable run, CTRL-P bootstraps editable presets into:

experiments/cartpole-v1/presets/

Use this path for benchmark-based runtime checks, training validation or HPO.

Option 2: Add a Built-in CTRL-P Environment¶

Create a package under:

src/ctrlp/environments/<env>/

Recommended package shape:

src/ctrlp/environments/<env>/
  __init__.py
  env.py
  model.py
  defaults/
    env.yml
    procgen.yml        # optional

What Goes Where¶

File

Responsibility

env.py

readable Gym lifecycle: __init__, reset, step, render, close

model.py

lower-level model, state, and update logic

defaults/env.yml

built-in environment defaults

defaults/procgen.yml

built-in ProcGen defaults when applicable

__init__.py

package export and environment registration metadata

Important

Keep the main environment lifecycle visible in env.py. Do not hide reset, step, and render inside a base class unless the shared logic is genuinely generic.

Registration¶

The package’s __init__.py should:

  • expose the environment class

  • define ENV_SPEC

  • provide get_env_specs()

The registry then discovers the package without a separate registration.py file.

Run a complete minimal example¶

The downloadable example implements the Gymnasium reset/step contract, consumes an EnvContext, and declares an EnvSpec. From the repository root after installation:

PYTHONPATH=src python docs/examples/counter_env.py

It runs Gymnasium’s environment checker and a three-action completion check; it creates no experiment, model or dataset. The source is intentionally a scalar counter so the registration/lifecycle contract stays visible.

"""Minimal EnvContext/EnvSpec example; run from the repository root."""
import gymnasium as gym
import numpy as np

from ctrlp.environments.context import EnvContext
from ctrlp.environments.spec import EnvSpec


class CounterEnv(gym.Env):
    """Choose decrement/increment until reaching a configured count."""

    metadata = {"render_modes": []}

    def __init__(self, context: EnvContext):
        self.goal = int(context.env.get("goal", 3))
        if self.goal < 1:
            raise ValueError("goal must be positive")
        self.action_space = gym.spaces.Discrete(2)
        self.observation_space = gym.spaces.Box(0, self.goal, shape=(1,), dtype=np.float32)
        self.value = 0

    def observation(self):
        return np.array([self.value], dtype=np.float32)

    def reset(self, *, seed=None, options=None):
        super().reset(seed=seed)
        self.value = 0
        return self.observation(), {"score": 0.0}

    def step(self, action):
        if not self.action_space.contains(action):
            raise ValueError("action must be 0 or 1")
        self.value = int(np.clip(self.value + (1 if action else -1), 0, self.goal))
        done = self.value == self.goal
        return self.observation(), float(done), done, False, {"score": float(done)}


ENV_SPEC = EnvSpec(id="example/counter-v0", slug="counter", entry_point="counter_env:CounterEnv")


def get_env_specs():
    return [ENV_SPEC]


if __name__ == "__main__":
    from gymnasium.utils.env_checker import check_env
    context = EnvContext(env={"goal": 3}, reward={}, procgen={}, paths={})
    env = CounterEnv(context)
    check_env(env, skip_render_check=True)
    env.reset(seed=0)
    for _ in range(3):
        observation, reward, terminated, truncated, info = env.step(1)
    assert terminated and not truncated and reward == 1.0
    env.close()
    print("Counter environment: Gymnasium contract and completion checked")

Download the complete example.

To make a built-in package, move the lifecycle into src/ctrlp/environments/counter/env.py, expose the class/spec from __init__.py, and change the entry point to ctrlp.environments.counter:CounterEnv. Add package defaults and an authored experiments/counter/runs/<task>/<algo>/<run>/run.yml with selectors matching its path. Resolve it, then run check and focused reset/step/termination tests. A changed scientific contract needs a distinct identity.

Use the shared physical-state and scene contracts only when the environment actually provides those quantities. Julia and Mirage demonstrate separate integration paths; see architecture and trainer compatibility.

Defaults And Outputs¶

Built-in package defaults live in defaults/; task-level overrides live in:

experiments/<env>/

Run outputs go to:

experiments/<env>/runs/<task>/<algo>/<run>/

Shared Code¶

Use these shared areas instead of copying utilities into the env package:

  • ctrlp.environments.common for shared environment substrate and control helpers

  • ctrlp.visualization for generic viewer infrastructure

  • ctrlp.common.environments for wrappers and vector envs

  • ctrlp.common.procgen for ProcGen support

Tip

A good built-in environment package stays small: keep the lifecycle in env.py, move heavy state logic into model.py, and reuse shared infrastructure where possible.
