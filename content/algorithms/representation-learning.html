Imitation and representation learning¶

The named representation controls and their datasets are local study inputs. Stage them separately to run the examples below.

Behavioral cloning (BC) fits a policy to recorded demonstrations. Representation learning additionally fits an observation encoder, then can freeze that encoder while learning an action head. PPO continuation is a separate stage, initialized through a verified model bundle.

Choose the execution path¶

Ordinary bc controls use train with declared datasets and train/validation sets. pretrain normally prepares rollout datasets, or trains a transition model when its explicit target is trans; it does not select the native autoencoder pipeline. The native representation workflow is configured under overrides.algo.imitation.representation on an authored PPO control.

The current implementation is deliberately specific: native JAX execution, verified demonstration caches and the qualified (15, 40, 40) observation contract. It is not a general encoder-fitting API for every environment.

representation.phase

Operation

prepare

Verify the pinned cache, replay training data and build geometry-grouped preparation views

sizing

Measure resource/sample sizing for the prepared corpus

qualification

Run the declared representation qualification diagnostics

mask_qualification

Check the mask-related qualification contract

autoencoder

Fit an encoder/decoder from observations and retain encoder artifacts

ordinary_bc

Fit action imitation without freezing the encoder

frozen_bc

Fit BC with the qualified/explicitly initialized encoder frozen

autoencoder_bc

Execute the composed autoencoder then frozen-BC pipeline

Inspect shipped controls¶

ctrlp experiments/lite/pbf-v2/runs/thermo_large/ppo/representation-prepare/run.yml --mode resolve
ctrlp experiments/lite/pbf-v2/runs/thermo_large/ppo/representation-ae-bc/run.yml --mode resolve

These controls require the owning study’s reward preset at experiments/lite/pbf-v2/presets/reward/thermo_large/zigzag-paper1.yml even for resolution. That research preset is not shipped in a clean checkout. The documentation checker reports the examples as unavailable until it is staged; it does not count them as passed. Training additionally requires the matching host-local cache and qualified inputs. The controls carry fixed dataset/cache hashes and research budgets; they are not first-run smoke examples. Use a new run identity for a different corpus or experiment. Execute data preparation and training only within the approved study workflow when remote resources are used.

A minimal representation fragment has this shape; supply real identities from verified data rather than copying placeholders:

overrides:
  algo:
    imitation:
      representation:
        phase: prepare
        cache_key: <64-character lowercase SHA256>
        dataset_sha256: <64-character lowercase SHA256>

Other imitation fields supply episode/sample budgets, batch size and fitting settings. The parser validates phase-specific preparation pins. For prepared-data reuse, preparation_key and preparation_manifest_sha256 must be supplied together; the prepare phase creates them and cannot select an existing pin.

Splits, fitting and artifacts¶

The corpus groups related geometry when constructing training and validation views. Preserve those groups and content identities; splitting individual transitions at random can leak the same geometry across partitions. Raw demonstrations remain the original evidence. Replayed/derived observations are new preparation artifacts and must not be described as fresh demonstrations.

runtime.train.timesteps bounds sample presentations for these fits rather than proving new simulator interactions. Logs report representation loss, epoch, presentations and fitting time. representation.json records phase progress and qualification status in the agent’s imitation directory. A fitted file may remain ineligible pending gates; inspect its receipt before promoting it.

Frozen BC requires qualified pipeline state or explicit verified encoder initialization. development_final_only is an explicit development fitting option, rejected for preparation/sizing/qualification phases. It is not evidence that a candidate passed selection gates.

For PPO, create a separate run and use ctrlp.model-initialization.v1 from the selected bundle. Decide explicitly which parameters load, which train, whether the encoder stays frozen and whether optimizer state is reset. Preserve dataset and normalization identities throughout the handoff.

Interpretation¶

Reconstruction loss, imitation accuracy and rollout reward measure different things. Assess scratch, BC/encoder initialization and PPO continuation on matched held-out cases before claiming a control improvement. Separate imitation and thermal cohorts do not establish direct transfer between them.

Owners: src/ctrlp/learning/algorithms/imitation/representation.py, representation_data.py, representation_qualification.py, representation_mask_qualification.py and representation_size.py in that same package. Continue with DAPH guidance or physical datasets.
